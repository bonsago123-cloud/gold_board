# v3 — 금 단독 과제 검증 + 달러·원화 표시

1. ZIP 안 gold-board 폴더의 **내용**을 기존 저장소에 덮어씁니다. package.json은 저장소 루트에 둡니다.
2. 기존에 002_four_assets.sql을 적용해 네 종목 기록을 수집했다면 Supabase SQL Editor에서 **sql/003_restore_gold_records.sql**을 실행합니다. 네 종목 저장소의 실제 금 기록을 gold_*로 복사하며 같은 날짜의 더 최신 기록을 보존합니다. 삭제는 없습니다. 001만 사용했다면 추가 SQL 없이 사용할 수 있습니다. 처음 설치라면 001_gold_board.sql 실행이 필요합니다.
3. 기존 SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY는 유지합니다. **금 검증과 환율에는 새 API 키나 결제가 필요하지 않습니다.** 환율은 키 없는 ExchangeRate-API 공개 API를 사용합니다.
4. Vercel 재배포 후 Ctrl+F5. 금 탭에서 달러·원화, 환율과 기준 시각을 확인합니다.
5. 하단 과제 검증 → **금 조회·기록·검증**. 다른 실제 KST 날짜에 다시 수집하여 금 두 날짜 증빙과 변화값을 확인합니다. 금 실패·복구 검사와 공식 전체 순서 검사도 실행합니다.

## 구분

- 메인 금과 검증 페이지는 /api/board, gold_* 저장소를 같이 사용합니다. 예약 수집도 금만 수행합니다.
- 은·석유·밀은 추가 조회 기능으로 유지합니다. 기존 추가 종목 저장은 002 SQL을 사용합니다. 석유·밀의 숫자 가격에는 여전히 유효한 COMMODITIES_API_KEY가 필요합니다. 미연결이면 달러/원화 값은 모두 비어 있고, 과제 금 검증에는 영향을 주지 않습니다. 차트는 별도 외부 제공 화면입니다.
- 원화 = 달러 원천값 × 최신 제공 USD/KRW 환율. 적용 단위는 원래 단위와 같습니다. 원화 표시는 1원 단위 반올림이며 국내 매매가·세금·수수료를 뜻하지 않습니다.
- 환율은 제공자 기준 **하루 1회 갱신**입니다. 브라우저는 캐시를 재사용하며 다음 갱신 시각 또는 1시간 경과 후 재확인합니다. 실시간 환율로 표시하지 않습니다.
- 환율 실패 시 이전 환율을 유지하고 ‘이전 환율 사용’을 표시합니다. 저장 환율이 없으면 원화 환산 불가로 표시합니다. 달러 가격은 유지됩니다.
- 일별 기록의 원화 열도 현재 적용 환율로 계산하며, 당시 원화 기록이 아닙니다. 과제 원자료·저장값 대조와 변화 계산은 USD 기준입니다.
- 금 기존 최초 두 실제 날짜는 서버 evidence로 유지합니다. 이후 날짜의 기록을 삭제하지 않습니다.

실제 배포에서 외부 데이터 접속, 본인의 DB 저장, 두 날짜 증빙과 과정 발급 영수증은 별도로 확인해야 합니다.
