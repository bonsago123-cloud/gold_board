# 실제 사이트 전체 기능 실행 규칙

이 문서는 저장소만 받은 모든 후속 AI에게 적용한다. 역할 이름이나 이전 대화는 필요하지 않다. 과제 원문과 `HANDOFF.json` 및 이전 검사부터 확인하고 기존 고정 검사 10개·기대값·공통 상한을 바꾸지 않는다.

## 시작 및 재검사
1. `https://goldboard-omega.vercel.app`을 로그아웃된 새 브라우저에서 열고 시작·종료 시각(KST), 실제 HEAD, 브라우저 종류, 배포 버전 확인 여부를 기록한다. 배포 버전을 확인하지 못하면 추측하지 않는다.
2. Node 24 환경에서 `npm ci`, `npm run handoff:resume`, `npm run site:check`를 실행한다. `test-output/site-check/`에 항목별 JSON·Markdown·실패 화면이 생성된다. 실시간 접속 불가면 UNVERIFIED다.
3. 코드와 실제 페이지를 기준으로 모든 입력·탭·버튼·링크·다운로드·그래프 조작을 목록화한다. 아래 표는 시작 목록이며 동적 버튼·오류 시 재시도도 포함한다.
4. 결과에 FAIL/UNVERIFIED가 있어도 다른 항목은 전부 시행한다. 실패 원인 수정 → 해당 기능 재검사 → 전체 재검사를 수행한다.

## 실제 기능 확인 목록

| 위치 | 기능 | 확인할 점 |
|---|---|---|
| `/` | 금·은 탭 각각, 실제 조회 버튼 | 실제 양수값·USD 및 원화·단위·출처·원천/조회 시각, 실패 이유 |
| `/` | 자동 조회 켜기·끄기 | 상태 전환과 실제 정해진 간격의 요청, 중단 후 요청 없음 |
| `/` | 비트코인 조회·오류·재시도 | 실제 BTC 값 USD/BTC·출처·시각 또는 실패, 대기·마지막 정상값 보존 |
| `/` | 환율 다시 확인 및 오류 재시도 | 출처와 값, 정상·실패 안내 |
| `/` | 차트 각 시간 간격 및 새로고침, 확대·축소 | 선택한 종목·시간축의 실제 위젯, 빈 화면이나 연결 실패 감지 |
| `/` | 일별 기록, 금/은별 저장값 | 기록 행·KST 날짜·단위·조회시각, 실제 기록 없으면 미확인 |
| `/` | 이동 링크·외부 출처 링크 | 페이지 이동 및 유효한 목적지 |
| `/verify.html` | 금 조회·기록·검증, 기록 새로 읽기 | 실제 DB 및 외부 조회 결과, 저장/표시값 일치 |
| `/verify.html` | 실제 이틀·변화값·JSON 다운로드 | 실재하는 서로 다른 두 날짜와 값, 다운로드 내용·이름 |
| `/verify.html` | 합성 5종 실패·복구 | 5/5 및 상태 유지·복구를 실데이터와 혼동하지 않기 |
| `/verify.html` | 공식 fixture 개별·전체·초기화·재시도·펼치기 | manifest 무결성, 각 fixture 실제 예상값·정상/실패/복구 |
| `/silver-verify.html` | 은 조회·기록·이틀·JSON·실패/복구·공식 검사 | 은 데이터로 별도 검증, 합성 날짜 사용 금지 |
| `/official.html` | 공식 검사 링크 이동 | `/verify.html#official-tests`로 연결 |
| `/task5.html` | 비교표·증거·상태 링크 | 원본 측정값과 별도 현재 BLOCKED/COMPLETE 구분 |
| `/handoff.html` | 상태·검사별 결과·시각·다음 행동·링크 | 최신성, 상태가 PASS라고 근거 없이 표현하지 않기 |

자동 `site:check`가 기본 기능을 자동 실행하더라도 이 목록 중 자동화되지 않은 항목은 직접 실행해서 기록한다. 특히 실제 자동 갱신 시간 간격, 외부 차트 확대/축소, 외부 링크 목적지의 실접속, 실데이터 두 날짜 증빙은 스크립트의 버튼 작동 결과만으로 PASS 처리하지 않는다.

## 판정과 증거
- 기능 단위로 ID, 페이지, 입력/행동, 기대값, 실제 관찰, PASS/FAIL/UNVERIFIED, 시각·증거 경로를 기록한다. 오류 안내가 잘 나와도 실제 가격 조회 실패는 FAIL이다.
- 합성 fixture 성공과 실제 API 조회 성공을 혼동하지 않는다. 누락되거나 실증되지 않은 행은 UNVERIFIED로 남긴다.
- 네트워크를 일시 차단하는 실패·복구 검사는 격리 브라우저 또는 기존 합성 실험으로만 수행하고 실제 운영 DB 데이터를 삭제하지 않는다.
- 기존 공식 fixture, 검사 코드, 금·은·Supabase 기록, 키·비밀값·개인정보를 변경하지 않는다.
- `test-output/site-check/report.md`와 `result.json` 및 오류 캡처를 읽고, 중요한 근거는 `docs/handoff/site-check-latest.md`와 역사 파일로 보존한다. 빈 템플릿을 결과로 제출하지 않는다.
- `npm run handoff:finish`가 갱신한 `docs/handoff/current.md`의 7항목에 사이트 보고서 경로와 실패·미확인 항목을 연결한다. 이후 다시 finish를 실행하면 생성 문서가 덮어써질 수 있으므로 별도 기록을 보존한다.
- CI에서는 기존 gate가 FAIL이라도 `site:check` 단계가 별도로 실행되며 실패는 무시되지 않는다. `site-check-evidence` artifact를 확인한다. 증거가 없으면 PASS로 주장하지 않는다.

현재 활성 차트 고정10개는 docs/task5/bitcoin-chart/fixed-tests.json이며 기존 현재가 고정10개는 회귀 검사로 보존한다. 구리 검사와 과거 결과는 보존한다.
현재 차트의 자동검사 밖 증거는 handoff/chart/review.json에 NEXT.md의 형식대로 기록한다. 이전 현재가 증거 handoff/bitcoin/manual.json은 보존한다.
