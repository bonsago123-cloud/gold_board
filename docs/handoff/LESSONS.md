# 자동화 시도에서 확인한 문제와 적용한 해결

이 문서는 대화 전문을 포함하지 않는다. 2026-10-14 조회한 과거 대화 요약과 저장소 ef03f512cf265d55240452acb8743b487b466c9b의 실제 파일을 근거로 작성했다.
사용자가 언급한 5개 대화의 전문 전체를 확보한 것은 아니다. 아래 범위를 넘어 “전부 읽었다”고 주장하지 않는다.

| 확인 범위 | 문제 | 이번 적용 |
|---|---|---|
| A 시작/인계 기록 및 10월12일 대화 검색 | 로컬 수정과 GitHub 업로드 혼동 | 현재 HEAD와 작업트리 digest를 함께 기록; 업로드 완료 별도 검증 |
| 에이전트 B 관련 저장소 handoff-gaps | 실제 사용량·모델 차이·학생 판단 없음 | BTC 전용 기록 분리, 미확인 값으로 submission 차단 |
| 에이전트 C 대화 검색/조사 파일 | 모의10개 통과지만 실제 구리404; 조사파일을 수정본처럼 설명 | synthetic/live/deployment/site를 별도 gate로 처리; 실패면 완료 금지 |
| 구리 오류 처리·텍스트 인계 대화 | “모든 기능 해라”만 있고 다음 AI가 실행 안 함 | 루트 AGENTS에 명령·반복·종료 절차, finish에서 전체 사이트 검사 필수 |
| 에이전트 D 대화 검색/현 소스 | upload 폴더 지침 누락, API 실패가 전체 브라우저 검사 차단 | 루트가 유일 시작점; 독립 site gate로 선행 API 실패와 무관하게 실행 |
| 현재 사용자 결정 | 구리 고정검사를 BTC로 바꾸면 원래 비교 훼손 | 구리 실패/검사 보존, BTC 별도10개·freeze·측정; 화면/빌드에서 구리 제거 |

## 계속 지킬 해결책
- 실패가 남아 있으면 구체적 첫 FAIL과 수정 파일을 제시한다. 조사 기록을 기능 수정으로 부르지 않는다.
- 합성 검사 성공, 실제 API 성공, 브라우저 동작, 배포 일치, 과제 증빙은 서로 다른 증거다.
- 모든 gate를 계속 돌리고 예외·설치 실패도 UNVERIFIED 기록. 비정상 종료 시 VERIFYING은 완료가 아니다.
- 매 실행 이력·이전 실행 해시를 보존한다. site 보고서도 실행별 폴더에 복사하고 CI artifact에 담는다.
- 수정 중 소스가 바뀌면 무결성 FAIL. 60분 지난 기록이나 다른 digest는 다시 검증한다.
- 최초 BTC commit과 freeze를 대조한다. 검사 변경 없이 구현을 바꾼다.
- API가 막히면 같은 실패만 반복하지 말고 원인/시도/다음 가설을 기록한다. 외부 접근 차단을 제공자404라고 쓰지 않는다.
- UI 미완성은 “구현 중”, 가격은 —로 표시한다. 샘플 가격을 실제 가격처럼 넣지 않는다.
- 새 AI 자동 호출은 구현하지 않았다. 사용자 시작 → 저장소 읽기 → 검사/수정 → 인계가 자동화 범위다.
- 완벽한 무인 완성을 보장하지 않는다. 검증하지 못한 범위가 완료로 둔갑하지 않게 하는 것이 이 절차의 목적이다.

## 이번 환경의 추가 확인
- BTC API 직접 GET은 HTTP200, 정상 스키마와 CORS로 통과했다.
- Playwright Chromium 다운로드가 손상된 ZIP 응답으로 실패했다. 브라우저 전체 검사는 UNVERIFIED이며 API 성공으로 대신하지 않는다.
- BTC 화면은 다음 AI의 구현을 위해 명시적으로 미완성이다. 구리 원천 재조사를 계속할 이유가 없다.
