## 재현·통과 확인 4줄

어디로 가나요: 위 공개 결과물 URL의 실제 정보판·실패 재생실·기록 대조로 갑니다.

무엇을 하나요(3단계 이내): ① 실제 금시세 조회 ② 실패 재생실에서 정상→실패5종→다음 날 복구 재생 ③ 기록 대조에서 서로 다른 실제 KST 날짜 2건과 변화값을 확인합니다.

무엇이 보이면 통과: 값·단위·출처·원천 시각·조회 시각·Asia/Seoul이 보이고, 원자료·저장값·화면값이 일치하며, 실패 후 마지막 정상값/stale 보존, 공식 T04-RECOVER-D2 후 fresh/none 및 다음 날짜 1행 추가, 실제 이틀 기록과 변화 계산이 일치합니다.

안 될 때: 지연·원천 거절·호출 제한·오프라인·형식 변경마다 원인과 다시 시도가 구분되어 보입니다. 공식 검사 실패, 실제 날짜 부족, 저장소 미연결은 완료로 표시하지 않습니다.

## AI와 내 판단 3줄

AI에게 맡긴 일: 국제 금시세 정보판의 화면, 공개 원천 조회, Supabase 저장 SQL, Vercel 설정 파일, 실패 보존·복구 로직과 자체 자동 검사를 작성하도록 맡겼다.

내가 판단한 일: 과제의 주제를 국제 금시세로 정하고 Supabase와 Vercel을 사용하기로 했다. 배포와 DB 설정은 직접 하기로 결정했다.

AI 제안을 따르지 않은 일: AI가 Vercel에 직접 접근해 배포하려던 흐름을 따르지 않고, 내가 직접 배포할 수 있는 파일을 받는 방식으로 변경했다.
