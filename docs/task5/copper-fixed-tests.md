# 과제5 고정 검사 — 구리 개선 기능

## 개선점 한 개
기존 금·은 정보판에 **구리(CU) 현재 시세 조회 기능**을 추가한다.

데이터 원천: `https://metalmarket.cash/api/v1/prices/copper`

기본 REST는 인증 없이 사용하며, 구리 가격 단위는 `USD/t`로 취급한다.

## AI A / AI B 공통 상한
- 시간 상한: 각각 30분
- 요청 수 상한: 각각 10회
- 검사 수: 정확히 10개
- 검사 삭제: 금지
- 검사 완화: 금지
- 기대값 변경: 금지

## 두 AI에 사용하는 동일한 최초 요청
> 이 저장소와 저장소 안의 인수인계 문서만 보고 현재 기능을 이어서 작업하라. 이전 AI와의 대화 내용은 사용하지 않는다. `HANDOFF.json`이 가리키는 고정 검사 10개를 삭제·완화·기대값 변경 없이 만족시켜라. 기존 금·은 기능과 과제4 검증은 깨뜨리지 마라.

## 고정 검사 10개

| ID | 입력 | 관찰 가능한 기대값 |
|---|---|---|
| T05-CU01 | 메인 페이지를 연다. | 기존 금·은 화면과 별도로 `구리 시세` 영역과 `구리 조회` 버튼이 보인다. |
| T05-CU02 | 정상 구리 JSON(id=copper, symbol=CU, price>0, unit=USD/t)을 정규화한다. | CU, 양수 가격, USD/t, 조회 시각, 공개 출처 URL이 보존된다. |
| T05-CU03 | 가격이 0/음수/문자이거나 unit이 USD/t가 아닌 응답을 넣는다. | 잘못된 응답을 정상 가격으로 표시하지 않고 형식 오류로 판정한다. |
| T05-CU04 | `구리 조회`를 눌러 정상 응답을 받는다. | 정확한 공개 엔드포인트를 Authorization 헤더 없이 GET하고 가격을 표시한다. |
| T05-CU05 | 정상 응답을 받은다. | 화면에 가격, `USD/t`, 조회 시각, MetalMarket.cash 출처가 함께 표시된다. |
| T05-CU06 | 정상 조회 뒤 다음 조회가 실패한다. | 마지막 정상 구리 가격은 유지되고 상태가 `stale`로 바뀐다. |
| T05-CU07 | HTTP 429와 Retry-After를 받는다. | 오류가 `rate_limited`로 구분되고 지정된 재시도 대기 시간이 적용된다. |
| T05-CU08 | 타임아웃과 일반 네트워크 실패를 각각 발생시킨다. | 타임아웃은 `timeout`, 일반 연결 실패는 `offline`으로 구분된다. |
| T05-CU09 | 정상값이 있는 상태에서 실패한다. | 이전 가격을 지우지 않고 실패 원인과 다시 시도 안내가 화면에 보인다. |
| T05-CU10 | 실패 직후 사용자가 연속으로 조회를 누른다. | 재시도 가능 시각 전에는 중복 요청을 막고, 대기 후 정상 응답이면 `fresh / none`으로 복구된다. |

## A/B 분담 목표
- AI A 목표: T05-CU01~T05-CU05까지 성공 경로 구현
- AI B 목표: 저장소와 인수인계만 보고 T05-CU06~T05-CU10을 추가해 최종 10/10 완성

분담 목표는 검사 기대값을 바꾸는 것이 아니라 의도적인 중단 지점을 정의한 것이다.
