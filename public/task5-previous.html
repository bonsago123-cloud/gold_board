이 페이지는 이전 사이클의 보존 기록입니다. 현재 작업과 제출 판정은 새 작업 페이지를 보세요.

과제 5 · 대화가 끊겨도 이어지는 프로젝트

저장소 인수인계의 실패와 성공

현재가 구현 2/10 → 10/10 · 차트와 공통 UI 완성 · 과거 실패 보존

정보판 · 소스 저장소

결과 요약

대화가 바뀌어도 저장소와 일곱 항목 인수인계를 통해 작업을 이어가는 절차를 구축했다. 구리 조회에서는 실제 원천 404를 해결하지 못했으나, 절차를 보완한 뒤 비트코인 현재가를 다음 실행에서 완성했다. 같은 고정 검사 결과는 2/10 → 10/10이다. 이후 차트·탭·공통 UI·원화 표시까지 구현했다.

제출의 중심 비교는 비트코인 현재가 조회 한 기능이다. 구리와 차트는 별도 작업으로 기록하며, 서로 다른 검사를 하나의 성공률로 합산하지 않는다.

기능 구현 결과와 제출 조건의 증빙은 구분한다. 서로 다른 서비스·모델 사용 및 엄격한 이전 대화 미제공 조건은 기록만으로 확정할 수 없다. 학생의 도구 선택 기준 확인도 남아 있다. 이 보고서는 확인되지 않은 조건을 통과로 처리하지 않는다.

자동화한 작업

사용자가 새 AI를 시작하면 AI가 AGENTS.md와 현재 인수인계를 읽고, 시작 소스·시각·받은 문서 해시를 기록한다. 구현 후 독립 검사를 실행하고 결과·실패 원인·남은 작업·다음 인수인계를 남긴다. GitHub Actions는 업로드 후 검사와 증거 보관을 수행한다. 다른 AI를 자동으로 호출하는 시스템은 아니다.

짧은 확인 방법 — 4줄

① 위치: 이 공개 비교 보고서의 “이름을 가린 비교표”와 “작업 순서와 고정 소스”.

② 행동: 비교표 보기 → 종료 10/10 기록 열기 → 받은 인수인계 원문 보기.

③ 통과 모습: 같은 현재가 검사 10개, 2/10에서 10/10으로 이어진 결과, 순서가 맞는 소스 버전과 동일 인계 해시.

④ 안 될 때 모습: 자료가 열리지 않거나 ID·해시가 다르거나 필수 증빙이 없으면 해당 조건은 확인 불가로 표시된다.

AI와 나의 판단 — 3줄

① AI에게 맡긴 일: 인수인계 자동화 절차, 비트코인 구현, 검사 및 실패·성공 기록 정리.

② 직접 판단한 일: 구리 대신 비트코인을 선택했고, 금·은과 같은 탭·UI 및 원화 표시를 요청했으며 최종 사이트 동작을 확인했다.

③ AI 제안을 따르지 않은 일: 이미 완성한 기능을 다른 AI에게 다시 검사시키거나 새 작업을 만들자는 제안을 따르지 않고, 기존 실패와 성공 과정으로 제출하도록 결정했다.

위 세 줄은 사용자가 실제로 요청·결정한 내용을 요약했다.

도구 선택 기준 — 학생 확인 필요: 다음 작업에서는 저장소만으로 이어받아 같은 검사를 통과시키고, 시간과 요청 수를 적게 쓰는 도구를 먼저 선택한다. 이 문장은 제안이며 학생이 확정한 기준으로 간주하지 않는다.
